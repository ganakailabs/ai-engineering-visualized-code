# ADR-001: Split the request path from the job path

Status: accepted (lab). Date: the book's simulated date, 2026-10-04.

## Context

Through Volume 3 the Northwind Goods assistant ran `handle_ticket()` in one process.
A refund can wait days for a courier or a person (Vol 2), and a model call can take
seconds. Neither fits inside an HTTP request that a customer is waiting on, and a
process that dies mid-refund must not pay twice.

## Decision

- The API accepts a ticket, takes identity (tenant_id, customer_id) from the login
  session only, writes a job to a queue and answers `202` with the job id.
- The job id is the business operation id, so a client retry is the same job.
- Workers take a job with a lease (a time-limited claim). Only the lease holder may
  finish the job. When a worker dies, the lease runs out and another worker resumes
  from stored state.
- Writes (refunds) go through the Vol 2 ledger with a key derived from the job id;
  a resumed job reconciles with the payment record before any retry.

## Consequences

- The customer sees "accepted" quickly; the answer arrives later (Ch 8 streams it).
- Every job must be resumable from state; in-memory progress is lost on a crash.
- A lease that is too short lets a slow but live worker lose its job; the fence in
  `Queue.complete()` stops that worker from finishing it. A lease that is too long
  delays recovery. The lab's 3 seconds is chosen for a fast test, not tuned.

## What the lab does not prove (the reference path)

The lab uses Python's `http.server`, which its documentation says "is not recommended
for production" and "only implements basic security checks". A deployment still needs,
and this book does not test:

- **Authentication** with a real identity provider, not a fixture session table.
- **TLS termination** at a proxy or load balancer in front of the API.
- **Process supervision**: something that restarts dead workers and the API.
- **Readiness and liveness checks** the platform can probe before sending traffic.
- **Durable storage**: a managed database and queue with backups, not one SQLite file.
- **Secrets** from a secret store, never from the repo or the prompt.
